## 📋 1. Functional requirements

Lusiad’s requirements describe how a developer edits a Java program as a model and inspects its evolution. The 20 user stories fall into six groups.

| User stories | What the developer can do |
| --- | --- |
| US01 | Create and manage modeling projects associated with Java codebases. |
| US02–US06 | Insert and rearrange nested blocks, edit their properties, and navigate the model hierarchy. |
| US07–US09 | Manage project files and directories in the explorer. |
| US10–US14 | Manage branches, commits, and tags. |
| US15–US18 | Inspect individual changes, compare states, and navigate the history. |
| US19–US20 | Compare arbitrary versions and synchronize changes made outside Lusiad. |

## 🎯 2. Quality requirements

The usability requirements call for controls that can be understood without training, immediate feedback after an operation, and consistent use of colors, icons, and text. The performance target is a maximum of five seconds to load any function. Reliability requirements cover the integrity of stored changes and agreement between the model and the Java source on disk after each operation.
