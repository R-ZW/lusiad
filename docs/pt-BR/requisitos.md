## 📋 1. Requisitos funcionais

Os requisitos do Lusiad descrevem como o desenvolvedor edita um programa Java como modelo e acompanha sua evolução. As 20 histórias de usuário se distribuem em seis grupos.

| Histórias de usuário | O que o desenvolvedor pode fazer |
| --- | --- |
| US01 | Criar e gerenciar projetos de modelagem associados a bases de código Java. |
| US02–US06 | Inserir e reorganizar blocos aninhados, editar suas propriedades e navegar pela hierarquia do modelo. |
| US07–US09 | Gerenciar arquivos e diretórios do projeto pelo explorador. |
| US10–US14 | Gerenciar branches, commits e tags. |
| US15–US18 | Inspecionar mudanças individuais, comparar estados e navegar pelo histórico. |
| US19–US20 | Comparar versões arbitrárias e sincronizar mudanças realizadas fora do Lusiad. |

## 🎯 2. Requisitos de qualidade

Os requisitos de usabilidade preveem controles compreensíveis sem treinamento, retorno visual imediato após cada operação e uso consistente de cores, ícones e textos. A meta de desempenho é carregar qualquer função em até cinco segundos. Os requisitos de confiabilidade abrangem a integridade das mudanças registradas e a consistência entre o modelo e o código Java em disco após cada operação.
